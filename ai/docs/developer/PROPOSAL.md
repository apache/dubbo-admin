# Proposal 清单

## 1) 改进 ReAct 上下文管理

### 背景
- 当前上下文管理主要采用简单滑动窗口（按最近 N 轮截断历史）。
- 该策略实现简单，但会丢失早期关键事实、用户偏好与长期约束，导致长会话中回答稳定性下降。

### 问题
- 重要信息与噪声信息没有区分，窗口外内容被直接丢弃。
- 工具调用结果与决策依据难以被长期保留，影响后续推理一致性。
- 长对话下 token 利用率不高，容易出现“记住了最近内容，忘了关键上下文”。

### 目标
- 在不显著增加时延的前提下，提高长会话一致性与可追踪性。
- 保留关键事实、约束和工具结论，降低重复提问与上下文漂移。

### 建议方案
- 引入“分层记忆”：
  - 短期记忆：保留最近若干轮原始对话（现有滑动窗口）。
  - 长期记忆：对历史做结构化摘要（事实、偏好、约束、未完成事项）。
- 关键事件触发总结：在轮次阈值、主题切换、工具调用完成后增量更新摘要。
- 检索增强拼装：在构建 prompt 时按“近期对话 + 相关摘要 + 相关工具结果”组合上下文。
- 增加上下文预算策略：为系统指令、近期对话、摘要、工具结果分别设置 token 配额。

### 验收标准
- 长会话（>20 轮）关键事实保持率显著提升。
- 同类问题重复提问率下降，工具调用决策一致性提升。
- 平均响应时延和 token 消耗可控（相对当前实现在可接受范围内）。

## 2) Agent 推理稳定性治理（降低报错率并提升可诊断性）

### 背景
- 当前 Agent 推理过程稳定性不足，线上/联调场景中存在“经常报错”的体验问题。
- 出错时缺少充分上下文与接口调用证据，难以快速判断根因属于代码逻辑、模型能力或外部依赖。
- 缺少可量化的稳定性证明手段，优化前后效果不易评估。

### 核心问题
- 上下文窗口管理粗糙，无效信息占用 token，干扰模型判断并放大不稳定性。
- 错误日志与追踪信息不完整，缺少请求链路、模型输入输出摘要、工具调用实参/返回值、超时与重试信息。
- 缺少体系化稳定性验证（回归基线、压测、长会话/异常场景测试），无法持续证明改进有效。

### 目标
- 显著降低 Agent 推理阶段的报错率与中断率。
- 将常见故障定位时间缩短到可控范围，能够快速判定问题归因。
- 建立稳定性度量与回归机制，持续证明 Agent 在真实场景下稳定运行。

### 解决方向
- 上下文管理精细化：
  - 采用“近期对话 + 结构化摘要 + 相关工具结果”的分层上下文策略，替代纯滑动窗口。
  - 引入无效信息过滤、主题聚合和 token 预算分配，减少噪声上下文。
  - 在关键事件（轮次阈值、任务切换、工具完成/失败）触发增量总结。
- 观测与诊断增强：
  - 为每次会话/轮次生成稳定 `trace_id`，串联编排器、模型调用、工具调用、SSE 输出链路。
  - 统一结构化日志字段：`session_id`、`trace_id`、`stage`、`iteration`、`tool_name`、`latency_ms`、`error_type`。
  - 记录“可复现最小证据”：模型请求参数摘要、工具请求/响应摘要、错误堆栈与重试轨迹（脱敏后落盘）。
  - 建立错误分类与归因规则：代码逻辑错误、模型输出异常、外部依赖错误、配置错误。
- 稳定性证明体系：
  - 定义 SLI/SLO：成功率、超时率、平均/TP95 延迟、单会话报错次数、重试成功率。
  - 增加回归测试矩阵：并发会话、长对话、空/异常 tool calls、工具超时、部分失败恢复。
  - 建立固定评测集与基线报告，按版本对比稳定性指标并纳入发布门禁。

### 验收标准
- 关键路径报错率较当前基线下降（建议目标：下降 30% 以上）。
- 常见故障可在单次排查中完成归因，且日志可复现关键调用链路。
- 每次发布前自动产出稳定性报告，包含核心 SLI 对比与回归结果。

## 3) 多用户多线程并行能力建设

### 背景
- 当前 Agent 在并发访问场景下的会话隔离与并行处理能力不足，限制了多用户同时使用的稳定体验。
- 随着接入用户与会话增长，串行处理或共享可变状态会导致互相干扰、延迟升高和错误放大。

### 核心问题
- 会话级状态与组件级状态边界不清，存在上下文串话与并发安全风险。
- 推理、工具调用、流式输出链路缺少统一并发控制，易出现阻塞、超时和资源争用。
- 缺乏多用户并发压测与容量基线，无法评估系统可承载上限。

### 目标
- 支持多用户会话并行执行，确保会话间严格隔离。
- 在并发负载下保持可接受延迟和较低错误率。
- 建立并发容量评估和扩容策略，支撑后续规模增长。

### 解决方向
- 会话隔离与线程安全：
  - 明确会话级上下文、记忆、channels 的生命周期，禁止跨会话复用可变对象。
  - 对共享资源加锁或改为无锁安全结构，消除数据竞争与串话风险。
- 并发执行与资源治理：
  - 为模型调用、工具调用、SSE 推送增加并发配额、超时、重试与熔断策略。
  - 引入队列与背压机制，避免瞬时流量导致 goroutine 暴涨和下游雪崩。
  - 统一上下游 `context` 取消传播，确保请求结束后资源及时回收。
- 可观测与容量验证：
  - 增加并发维度监控：活跃会话数、排队长度、goroutine 数、TP95/TP99 延迟、错误率。
  - 建立多用户并发压测场景（如 50/100/200 并发会话）并形成基线报告。
  - 基于压测结果设定默认限流阈值与扩容建议。

### 验收标准
- 在目标并发规模下会话隔离正确，无跨会话数据污染。
- 并发压测通过既定 SLO（成功率、TP95 延迟、超时率）且资源使用稳定。
- 发布前具备固定并发回归用例与容量报告，异常可快速定位到具体链路。
